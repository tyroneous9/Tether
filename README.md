# Tether

Turn a knob and a servo turns to match. An STM32 Nucleo-F446RE reads a potentiometer with a timer-triggered ADC, moves the samples into RAM with DMA, averages them, and drives a hobby servo with hardware PWM. It also reports the commanded angle over UART.

```
TIM2 (1 kHz) ──TRGO──▶ ADC1 ──▶ DMA2 (circular) ──▶ adc_buf[20] ──▶ average ──▶ TIM3 PWM ──▶ servo
                                                                        │
                                                                        └──▶ USART2: "POS:<angle>"
```

## How it works

**Sampling.** TIM2 overflows every 1 ms and signals the ADC through its trigger output (TRGO), an internal connection with no pin and no CPU involvement. Each pulse starts one 12-bit conversion of the potentiometer on PA0. Because the timer starts each conversion, samples are exactly 1 ms apart no matter what the main loop is doing.

**Data movement.** DMA2 Stream 0 copies each result from the ADC data register into a 20-element `uint16_t` buffer. The DMA runs in circular mode with ADC DMA Continuous Requests enabled, so it wraps back to the start of the buffer and keeps going indefinitely. The CPU never waits on or copies a conversion. At 1 kHz, the buffer always holds the last 20 ms of readings, which is one servo period.

**Filtering.** The main loop averages the 20 samples, which reduces random ADC noise by about √20 ≈ 4.5×.

**Servo output.** TIM3 channel 1 generates the servo signal on PA6. With the 84 MHz timer clock, dividing by 84 (prescaler register 83) gives 1 µs ticks, and counting 20,000 ticks (period register 19999) gives the standard 50 Hz (20 ms) servo frame. The compare value is the pulse width in microseconds. The averaged reading is mapped linearly from 0–4095 onto 500–2400 µs, the measured end-to-end range of the servo used.

**Reporting.** Once per second, the firmware prints the commanded angle (0–180) on USART2 as a text line such as `POS:90`. A hobby servo has no position feedback, so this is the angle the firmware commanded, not a measurement.

## Hardware

| Part | Notes |
| --- | --- |
| STM32 Nucleo-F446RE | Clocked at 84 MHz from the internal HSI through the PLL |
| B10K potentiometer | 10 kΩ linear. Outer legs to 3.3 V and GND, wiper to A0 |
| SG90-class micro servo | Powered from its own 5 V supply |
| 5 V supply, ≥1 A | For the servo only. Its current spikes can reset the Nucleo if it shares the board's supply |
| 100–470 µF capacitor | Across the servo supply, near the servo |

### Pin assignments

| Function | MCU pin | Nucleo header | Peripheral |
| --- | --- | --- | --- |
| Potentiometer wiper | PA0 | A0 | ADC1 channel 0 |
| Servo signal | PA6 | D12 | TIM3 channel 1 (PWM) |
| Serial output | PA2 / PA3 | via ST-Link USB | USART2, 115200 8N1 |
| ADC trigger | (internal) | | TIM2 TRGO |

### Wiring notes

- **Power the potentiometer from 3.3 V, not 5 V.** The ADC input must stay between 0 V and 3.3 V.
- **Connect all grounds together:** the Nucleo, the servo supply and the servo.
- **The servo accepts the Nucleo's 3.3 V PWM signal directly.** Never connect the signal wire to the 5 V rail.

## Building and flashing

The project is generated by STM32CubeMX (`Tether.ioc`) and builds with CMake, Ninja and the GNU Arm toolchain (`arm-none-eabi-gcc`).

```bash
cmake --preset Debug
cmake --build --preset Debug
# output: build/Debug/Tether.elf
```

To flash and debug in VS Code with the STM32Cube extension, connect the Nucleo over USB and run the **"STM32Cube: Launch ST-Link GDB Server"** configuration. Any ST-Link flashing tool also works with the `.elf` file.

To see the output, open the ST-Link virtual COM port at 115200 baud:

```bash
picocom -b 115200 /dev/ttyACM0
```

CubeMX regenerates `Core/` and `Drivers/` and keeps only code inside `USER CODE BEGIN` / `USER CODE END` blocks. Keep any hand-written code inside those blocks.

## Known limitations

- **No deadband.** Small fluctuations in the averaged reading still reach the servo. If the servo jitters while the knob is still, add a threshold: update the servo only when the reading moves more than a few counts from the last value sent.
- **The servo is updated on every loop iteration**, not once per 20 ms frame. This is harmless, because the timer only applies a new compare value at the start of each frame.
- **Nominal input range.** The mapping assumes the potentiometer reads exactly 0–4095. A real potentiometer rarely reaches either end, so the servo may not quite reach its endpoints.
- **Startup jump.** PWM starts at the CubeMX default of 1500 µs (center) before the first average is available, so the servo briefly jumps to center at power-up.
- **Position reporting runs at 1 Hz.**
